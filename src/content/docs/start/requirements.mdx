Printing needs Linux 6.7 or newer. The check below tells you in one command whether your host qualifies.

## What the host needs

- **Architecture.** The images are built for amd64 only. An arm64 host, such as an Apple silicon machine or a Raspberry Pi, cannot run them natively.
- **Docker.** You need Docker with Compose v2. The quick start ran on Docker 28.0.4 with Compose 2.38.2, on Ubuntu 24.04 with Linux 7.0.
- **A kernel with Landlock ABI 4.** The host needs Linux 6.7 or newer, with Landlock enabled. Details are in the next section.
- **Ports.** The quick start publishes the app on port 8080 over plain HTTP on every network interface. It binds Postgres to loopback only. [Install for production](/start/production/) covers TLS.

Docker Desktop is untested. Run the check below inside the environment where the containers will run.

## Landlock and printing

Codex compiles every print job inside a sandbox that uses Landlock, a Linux kernel feature. The sandbox needs Landlock ABI 4, which arrived in Linux 6.7. There is no way to turn the sandbox off, and Codex never falls back to an unsandboxed compile. If the kernel has no Landlock, or an older version, the sandbox refuses to start.

On WSL2 with kernel 6.6, the sandbox refuses to start. Update the WSL kernel, or run Codex on a host with a newer kernel.

### What needs the sandbox

These features stop working on a host that fails the check:

- Quick preview in [Layout](/ui/layout/), and the template thumbnails. These run in the app container.
- Proofs.
- Export for printer, which makes the print PDF.
- Word export.
- EPUB export.

Proofs, Export for printer, Word export and EPUB export run in the worker container.

### What still works

- Markdown manuscript export and the source archive. Neither uses the sandbox.
- Every other part of the app. You can plan, write, research, cite sources, share a book and connect agents.

### Check your host

Run this on the host that will run the containers. It starts the sandbox from the worker image and runs `/usr/bin/true` inside it.

<Code code={sandboxCheck} lang="sh" title="Terminal" />

An exit code of 0 means the sandbox works and the sandbox starts on this host. An exit code of 125 with a line that starts with `codex-sandbox:` means the sandbox refused to start, and the message tells you why. Docker also exits with 125 when the daemon fails, for example when the image cannot be pulled. In that case Docker prints its own error and no `codex-sandbox:` line.

On a kernel with Landlock ABI 3, the output looks like this.

```text
codex-sandbox: Landlock ABI 3 cannot restrict TCP (needs 4); refusing to run
exit code: 125
```

On a kernel with no Landlock, the message starts with `codex-sandbox: this kernel has no Landlock`. The same message appears if the container runtime blocks the Landlock system calls.

### What you see when the sandbox refuses

A failed export lists the refusal on the export, and so does a failed proof. Each of those messages starts with the same sentence, followed by the text the sandbox printed.

```text
The print sandbox could not start: codex-sandbox: Landlock ABI 3 cannot restrict TCP (needs 4); refusing to run
```

A failed Quick preview shows a different message. The Layout screen says "The preview could not be made" with the detail "Something went wrong on the server." The screen gives no reason. A failed template thumbnail in the template library in settings shows a blank page and no message. For both, run `docker compose logs codex` and look for the error in the app container log.

In both cases the fix is on the host, not in Codex. See [Troubleshooting](/start/troubleshooting/).

  `CODEX_SANDBOX` sets the path to the `codex-sandbox` program. It does not turn the sandbox off. See the [configuration reference](/start/configuration/).
</Aside>
